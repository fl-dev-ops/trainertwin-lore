# Living wiki contract

Inspired by Karpathy's LLM wiki and the maintainer patterns in the Hermes wiki: sources are immutable, Markdown pages are persistent, and updates cite original evidence rather than other summaries. `prompts.py`, `sources.py`, and `core.py` enforce the machine-checkable part.

## Layers

Every relative path below is under `users/<slug>/` (default slug `olga`).

- `data/<channel>/**/*.{md,yaml,json,...}` — curated source of truth; recursively scanned. Non-text, hidden, and metadata-only files are not extracted. YAML with `turns` and Sarvam JSON with `diarized_transcript.entries` retain turn/time/speaker metadata. Other YAML/JSON are flattened to JSON-pointer text leaves. Markdown frontmatter supplies optional source URL, date and author. New YouTube `video/*.md` files have `transcript: true`, an optional `description` in frontmatter (not spoken evidence), and timestamped `### HH:MM:SS · Speaker N` turns preserved as individual source units. `data/.source-metadata.yaml` (excluded from scanning) can supply `date`, `url`, `author` by relative path when a source lacks them; no date is inferred from a filename or video title.
- `workspace/evidence/<source-id>-<revision>.jsonl` — one claim/observation per line, with raw source SHA-256, metadata hash, channel, original URL, author, `published_at` (ISO or null) and `date_basis`, source unit, locator, optional **within-video** timestamp, exact normalized excerpt, topic, type and context. `manifest/<source-id>.json` selects the active completed version. Older versions and per-call caches are not independent sources.
- `workspace/wiki/` — generated source, topic, category, channel and overview pages. Topics are shared across channels; a model-maintained `topic-map.json` consolidates labels in bounded batches before synthesis, while categories classify observation *type*. `index.md` navigates, `timeline.md` sorts by publication date (undated sources separately), and `log.md` records changes. `build` maintains only wiki pages. `workspace/reports/analysis.md` is compiled **on demand** by `analyze` from saved wiki Markdown (with a curated introductory section for Olga only), not from raw data or evidence cards; it is not another evidence source. `workspace/reports/timeline.md` keeps the chronology separate. Prior topic Markdown is editorial context during an update, never authority for citations. No silent ingestion of generated wiki pages.
- `workspace/verifications.jsonl` — append-only human-reviewed external claims, with evidence ID, status, public URL, note and checked time. The pipeline never performs external research or validates a URL's contents. `usage.jsonl` records provider token metadata when available.

## Evidence types and limits

`kind`: `fact_claim`, `self_report`, `belief`, `advice`, `teaching_move`, `observed_behavior`, `style`, `case_study`, `offering`.

`context`: `observed`, `advised`, `hypothetical`, `self_reported`, `third_party`.

A verbatim excerpt in a source proves **only that the words appear there**. Publication, offer, role-play, testimonial, and third-party speech require distinct interpretations. Speaker IDs from transcription are not identities. Multiple posts by the same author—or raw and cleaned copies of one recording—are not independent verification. Older evidence for changed files cannot justify current pages. Lint checks quote/locator integrity, source hashes, IDs and links, **not semantic truth or speaker attribution**. Human review is required before using claims externally.

## Update policy

1. Ingest new or changed sources; atomic manifest publication selects a complete evidence version. Unchanged sources and cached chunks cost no new calls. After a failed repair, invalid individual items are logged as `rejected-item` and excluded; review omissions.
2. Build only affected topic syntheses; give the model current evidence plus a bounded excerpt of the old page for editorial continuity. Cross-topic overview and category/channel indexes update afterward. No report is generated by `build`.
3. Run `lint`, then optionally `analyze` for a compiled report. A changed wiki makes an existing report stale; `lint` requires regenerating it. Inspect contradictions, guessed topics, temporal scope, duplicate raw/clean content, and attribution. Do not manually edit generated pages: corrections should be written to sources or the review overlay. If editorial corrections beyond fact verification are needed, add a protected corrections workflow rather than relying on edits to generated output.

Known limits: `analyze` compiles the wiki rather than writing a new interpretive essay; topic aliases are model-suggested rather than a reviewed ontology (review `topic-map.json`); model inference can be wrong even with a literal excerpt; automated pages do not capture visuals or audio; large sources cost money; removed sources deliberately block building until reviewed instead of silently erasing history. A page is a cited draft, not a claim to know anyone's private personality.
