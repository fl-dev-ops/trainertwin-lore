While everyone’s raving about coding agents and how they “barely code anymore,” I’m hearing a different, bleak story from engineering leaders I talk to. 

Looks like the new bottleneck isn’t writing code. It’s being able to explain why it was written that way, and what breaks if you change it.

A few points they brought up:
- Engineers are pushing code they don’t fully understand. Ask them to make a small change and they don’t know where to look. You can’t really call it out because everyone’s using AI, but you also can’t ignore that they can’t explain what they wrote.
- PR reviewers are drowning. The cognitive load of manually going through AI generated PRs is brutal, so they’re deploying their own agents to review. Which works if you know what to look for. If you don’t, you’re building mess on top of mess.
- “Building cost = 0” isn’t really true. Generating code is cheap, but development cost is going up. You’re constantly making decisions, handholding, fixing weird outputs. It’s like having a junior engineer assigned to you full time. Managing them sometimes takes more time than just doing it yourself.

One leader told me most of their team is becoming “thin human wrappers over coding agents.” Only a few people actually know how to dig into code and fix things.

I’m super bullish on coding agents. No way I’m killing the vibe on how good they are. But I do think we’re still learning how to operate with them well, and more importantly, how to take over when needed.

Human + AI for the win.

Randomly throwing people at tools won’t scale.
