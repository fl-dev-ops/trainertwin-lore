Super stoked to see @OReillyMedia feature our opinionated take, "Evals Are NOT All You Need" 

@kiritibadam and I talked about this on @lennysan's podcast, and a bunch of folks asked for more details, so we wrote up a longer version.

Link: https://t.co/TmYdq45IPz

Takeaways:
- Start small, 10 to 50 reference examples beats 500 noisy ones.
- Metrics without rubrics are just vibes.
- Measure with code checks if you can, they’re cheap and reliable.
- Use LLM judges only if you calibrate them against humans.
- Production will surprise you anyway, users will find edge cases you never imagined.
- Even 95 percent success at scale means lots of failures every day.
- The fix is a flywheel: monitor, sample signals, find failure modes, update metrics (or not), ship improvements, repeat.
- All failure mode do not need metrics, some are fix-and-move-on
- Metrics should evolve, capability metrics to improve, regression metrics to protect, saturated metrics to retire.

Build the flywheel, not the checkbox.
