Should you learn to code in 2026 and beyond?

It's the question every early-career person is asking, and there are a hundred takes on it. Here's mine (because why not :p)

Yes, you should learn to code. But what coding means now is different, and it should match how builders actually build today.

Start with the foundations of one coding language (Say, Python). Enough to read code, reason about it, spot obvious problems, and build small things yourself.

 Then run this loop, all of it agent-augmented, not manual:

⛳ Pick a real problem
 Start with something you actually want to solve. A product, a workflow, a pain point, anything real. Learning sticks better when you’re building toward something concrete.

⛳ Study credible open-source projects
 Before you build, look at strong open source projects or existing products in that space. Use your agent to help you understand how they work.

⛳ Ask design questions
 Don’t just look at what they built. Ask why they built it that way. What tradeoffs did they make? What breaks at scale? What architectural choices matter? What do you actually need to understand? This helps you for the next steps--

⛳ Write the spec
Now define your version clearly. What are you building? How should it behave? What constraints matter? What decisions need to be made before code gets written? Better understanding from before leads to you writing a better spec.

⛳ Build with agents
 Use agents to help you implement, compare approaches, and move faster. But stay in charge. The goal isn’t to hand over the thinking. The goal is to build with leverage.

⛳ Reverse engineer and improve
 Don’t just accept what the agent gives you. Ask why it chose that structure. Ask what alternatives it considered. Ask where the design might fail. Agents are sycophantic, so ask curious questions, not leading ones. Make them explain, compare, and critique. You will be in a much better position to reverse engineer your own product if you have spent time understanding good open source projects and their design decisions (from step 2) 

⛳ Then repeat. Study, spec, build, question, improve your judgment. That's the improvement loop for yourself. 

The meta-goal here is to become a builder who uses agents well, understands tradeoffs, and ships useful things. Pull in real engineering resources too, like Google's software engineering principles skills and  12-Factor App, and read them alongside your agent while you build.

Once you've run the loop a few times, get fancier: agents that critique each other, self-improving loops, automating parts of it. Just don't start there.

...And I do think there’s a big misunderstanding here. People think coding got easier. The answer is yes and no.
- Yes, because you don’t have to spend nearly as much effort on syntax.
- No, because the work has shifted. It’s gone from syntax heavy to design heavy. And going through this loop well still takes good amount of effort too, it's just "different"!
