😅 I was speaking to a few friends over the weekend, some of the smartest AI power users I know (including people building frontier models) and we realized we’d all independently developed the same weird behavior.

which is...the more we use AI, the less we seem to enjoy discussing execution work with other humans.

A lot of us now find it much more natural to brainstorm with AI, pressure test an idea with AI, figure out the implementation details with AI, and decide the exact route to take with AI.  Then the human conversation happens one level above that.

Imagine you’re building a new product feature. A few years ago, the team discussion might’ve been:
- What architecture should we use?
- How should the data flow work?
- Should this be synchronous or asynchronous?
- What happens when this fails?
- How should we structure the API?
- Which approach is going to be easier to maintain?

Now, for people who are extremely comfortable using tools like Claude Code or Codex, the human discussion can increasingly become:
- Should we build this feature?
- What should the user experience look like?
- What constraints actually matter?
- What tradeoff are we willing to make?

Okay, cool. Go build it...And then you have a fairly detailed conversation about the actual execution with AI.

And IMO this changes how teams communicate much more than we currently talk about. Human discussions get increasingly abstracted upward toward goals, product judgment, constraints, taste, priorities, and decisions.

AI absorbs more and more of the actual execution conversation underneath.

- On one hand, maybe it means humans spend less time debating implementation details and more time discussing the things that actually require shared context and judgment.

- On the other, a lot of technical learning, mentorship, and shared understanding historically came from those detailed discussions.

I can’t decide whether that’s a good thing. 🫠 🫠
